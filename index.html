A
Federated Learning
Privacy-preserving distributed model training across heterogeneous clients
▲ Emerging
Domain Signal: FL has matured from FedAvg variants (2020–22) to tackling data heterogeneity at scale, LLM fine-tuning, and real deployment challenges (stragglers, Byzantine clients, communication cost). The frontier in 2024–25 is personalized FL + communication compression + private aggregation for LLMs and edge scenarios. Top venues: NeurIPS, ICML, MLSys, OSDI, MobiSys.
A.1 Heterogeneous / Non-IID Data Handling ▶
Addresses statistical heterogeneity where clients have non-identically distributed data, causing model divergence. Key approaches: personalized FL, clustered FL, bi-level optimization, and federated distillation.
Problem: Global model accuracy degrades 20–40% under severe non-IID distributions
Representative Papers
FedProto: Federated Prototype Learning across Heterogeneous Clients
NeurIPS2022
Shares class prototypes (feature centroids) instead of gradients; model-architecture-agnostic FL for heterogeneous settings.
FedDF: Ensemble Distillation for Robust Model Fusion in Federated Learning
NeurIPS2022
Uses unlabeled public data for distillation-based aggregation, bypassing gradient averaging entirely.
pFedHN: Personalized Federated Learning using Hypernetworks
ICML2023
A hypernetwork on the server generates client-specific model weights, achieving personalization without local fine-tuning overhead.
FedSplit: An Algorithmic Framework for Fast Federated Optimization
NeurIPS2022
Operator-splitting methods for FL convergence under data heterogeneity; provable convergence guarantees.
FLoRA: Federated Fine-Tuning Large Language Models with Heterogeneous Low-Rank Adaptations
ICML2024
Federated LoRA aggregation that handles clients with different adapter ranks — critical for LLM FL deployments.
A.2 Communication Efficiency & Gradient Compression ▶
Reduces the communication bottleneck in FL: quantization, sparsification, structured compression, sketching, and over-the-air computation. Critical for mobile edge deployments.
Problem: Uplink bandwidth from millions of devices is the primary bottleneck
Representative Papers
QSGD: Communication-Efficient SGD via Gradient Quantization and Encoding
NeurIPS2022
Unbiased stochastic gradient quantization with theoretical error bounds; widely deployed baseline.
FedPAGE: A Fast Local Stochastic Gradient Method for Communication-Efficient Federated Learning
ICML2022
Variance-reduced gradient estimator (PAGE) reduces communication rounds by 3–5× for convergence.
FedSkip: Combating Statistical Heterogeneity with Federated Skip Aggregation
arXiv2022
Skip-layer aggregation selectively synchronizes layers to reduce communication while preserving accuracy.
GRACE: A Compressed Communication Framework for Distributed Machine Learning
ICLR2023
Unified benchmark + framework for 20+ gradient compression algorithms; evaluates communication-convergence tradeoffs.
A.3 Byzantine-Robust Aggregation ▶
Defends against malicious clients sending poisoned gradients. Techniques: robust estimators (median, trimmed mean), gradient filtering, server-side verification, and reputation systems.
Problem: Certifiable robustness vs. accuracy-privacy tradeoff under adaptive attacks
Representative Papers
FLTrust: Byzantine-robust Federated Learning via Trust Bootstrapping
NeurIPS2022
Server maintains a small clean dataset; assigns trust scores to clients based on cosine similarity to server gradient.
Byzantine-Resilient Federated Learning with Heterogeneous Data
ICML2023
Proves first convergence bounds for robust FL under both Byzantine attacks and data heterogeneity simultaneously.
FLAME: Taming Backdoors in Federated Learning
USENIX Sec2022
Clustering + noise addition on server to neutralize model poisoning while preserving accuracy.
A.4 Federated Learning + Large Language Models ▶
Fine-tuning LLMs (e.g., GPT, LLaMA) using federated approaches without centralizing sensitive text. Key challenges: model size, heterogeneous resources, adapter aggregation.
Problem: Billion-param models cannot be loaded on edge devices; gradient communication is impossibly large
Representative Papers
FedPETuning: When Federated Learning Meets the Parameter-Efficient Tuning Methods of Pre-trained Language Models
ACL2023
Benchmarks adapter, prefix, LoRA tuning methods for FL across NLP tasks; identifies best communication tradeoffs.
OpenFedLLM: Training Large Language Models on Decentralized Private Data via Federated Learning
arXiv2024
System framework for instruction-tuning LLMs across medical, legal, and financial silos without data sharing.
FedLoRA: When Federated Learning Meets Parameter-Efficient Fine-Tuning
MLSys2024
Efficient federated LoRA aggregation strategy addressing rank heterogeneity across resource-constrained clients.
Federated Full-Parameter Tuning of Billion-Sized Language Models with Communication Cost under 18 Kilobytes
ICML2024
Achieves full fine-tuning of 7B-param LLMs with sub-18KB per-round communication via perturbation-based gradient estimation.
A.5 Differential Privacy in FL ▶
Formal DP guarantees for gradient sharing in FL. Approaches: local DP (noise at client), central DP (noise at server), shuffle model. Key tension: privacy budget vs. model accuracy.
Problem: Useful DP-FL at ε<1 with non-IID data and model heterogeneity
Representative Papers
Federated Learning with Formal Differential Privacy Guarantees
ICML2022
Tight analysis of DP-SGD in FL; proves Rényi DP composition across rounds under subsampling.
Private FL via Shuffled Model and Secure Aggregation
NeurIPS2023
Combines shuffle privacy amplification with secure aggregation for a strong privacy-accuracy Pareto frontier.
DP-FORWARD: Fine-tuning and Inference of Language Models with Differential Privacy in Forward Pass
NeurIPS2023
Novel per-sample noise injection in forward pass for DP-LLM fine-tuning, avoiding costly gradient clipping.
A.6 System Efficiency: Asynchronous & Hierarchical FL ▶
Overcomes straggler bottleneck via asynchronous aggregation or hierarchical aggregation (device → edge → cloud). Reduces wall-clock training time significantly.
Problem: Synchronous FL wastes GPU time waiting for slowest client; stale gradients corrupt training
Representative Papers
PAPAYA: Practical, Private, and Scalable Federated Learning
MLSys2022
Production-grade asynchronous FL at Apple scale: 500M+ devices, handles drop-outs and staleness efficiently.
FedBuff: Buffered Asynchronous Federated Learning
ICLR2022
Maintains an update buffer; aggregates when buffer is full rather than waiting for all clients, reducing idle time.
Auxo: Heterogeneity-Mitigating Federated Learning via Scalable Client Clustering
MLSys2023
Clusters clients by model update similarity; trains per-cluster global models to mitigate stragglers and heterogeneity jointly.
A.7 Federated Unlearning ▶
Enables clients to request removal of their data's influence from a trained global model (GDPR "right to be forgotten") without full retraining. Open area with few solid results.
Problem: Certifiable unlearning verification without retraining from scratch
Representative Papers
Federated Unlearning with Knowledge Distillation
arXiv2023
Distillation-based unlearning method that erases specific clients' contributions without affecting remaining accuracy.
FedEraser: Enabling Efficient Client-Level Data Erasure in Federated Learning
ICLR2024
Calibration-based unlearning using historical training updates stored on the server for approximate erasure.
A.8 Cross-Device vs. Cross-Silo FL ▶
Cross-device: millions of mobile/IoT devices (high churn, low compute). Cross-silo: few institutions (hospitals, banks) with full participation. Different system design requirements and algorithms.
Problem: Cross-device FL requires sub-second client selection and differential device capabilities
Representative Papers
Flower: A Friendly Federated Learning Research Framework
MLSys2022
Open-source framework supporting 10M+ clients, evaluates cross-device and cross-silo FL under realistic conditions.
FedScale: Benchmarking Model and System Performance of Federated Learning at Scale
ICML2022
Realistic benchmark with 20+ datasets, 1000+ device traces, and system-level metrics for cross-device FL.

Open Research Gaps
◆Federated fine-tuning of 70B+ parameter LLMs
◆Certifiable unlearning with formal guarantees
◆FL under graph-structured client networks
◆Multi-task FL with task inference
◆Efficient DP-FL for ε < 1 at scale
B
Parallel Computing
Algorithms, runtime systems, and programming models for parallelism
◼ Saturated Core
Domain Signal: Classic parallel algorithms are mature. The active frontier (2022–25) is compiler-driven auto-parallelism for DNN workloads, RDMA-based distributed shared memory, task-based runtime systems, and GPU programming models. Key venues: SC, PPoPP, ASPLOS, EuroSys, HPCA, ICS.
B.1 Auto-Parallelism & Compiler-Based Scheduling ▶
Automatic partitioning of computation graphs across devices. Combines ILP/DP/RL with compiler IR transformations to find optimal tensor and pipeline parallel strategies.
Problem: Search space for 4D parallelism (data/tensor/pipeline/sequence) is exponential
Representative Papers
Alpa: Automating Inter- and Intra-Operator Parallelism for Distributed Deep Learning
OSDI2022
Two-level hierarchical search (inter-op pipeline + intra-op tensor parallel) via ILP; achieves near-manual performance automatically.
Unity: Accelerating DNN Training Through Joint Optimization of Algebraic Transformations and Parallelization
OSDI2022
Joint graph substitution and parallel strategy search in a unified framework; 2.4× speedup over Megatron-LM.
WLB-LLM: Workload-Balanced 4D Parallelism for LLM Training
OSDI2025
Jointly optimizes data/tensor/pipeline/sequence parallelism for LLMs under heterogeneous workload distributions.
TensorIR: An Abstraction for Automatic Tensorized Program Optimization
ASPLOS2023
New IR for tensor programs that exposes hardware intrinsics (e.g., tensor cores) for auto-scheduling.
B.2 GPU Programming Models & Kernel Optimization ▶
FlashAttention-style IO-aware kernels, Triton-based programming, CUDA graph optimization, and multi-GPU operator fusion. Active area driven by LLM workloads.
Problem: Memory bandwidth is the bottleneck for attention; FLOP utilization often <50%
Representative Papers
FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning
ICLR2024
2× speedup over FlashAttention-1 via better thread block tiling and warp-level parallelism; industry standard.
FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-Precision
NeurIPS2024
Hopper H100 specific optimizations: warpgroup async operations, FP8 support; 1.5–2× over FA2.
Triton: An Intermediate Language and Compiler for Tiled Neural Network Computations
MLSys2023
Python-embedded DSL for GPU kernel programming at tile granularity; enables non-CUDA-experts to write high-performance kernels.
B.3 Task-Based & Dataflow Runtime Systems ▶
Programming models where work is expressed as tasks with data dependencies (DAGs). Runtime handles scheduling, load balancing, and fault tolerance automatically. Examples: Legion, Regent, Dask, Ray.
Problem: Scheduling billions of fine-grained tasks with dynamic dependencies at microsecond granularity
Representative Papers
Pathways: Asynchronous Distributed Dataflow for ML
MLSys2022
Google's multi-controller dataflow system enabling efficient execution of ML models across heterogeneous accelerators (TPU, GPU).
Hydro: Surrogate-Based Hyperparameter Tuning Service in the Datacenter
OSDI2023
Cluster-level hyperparameter tuning system using surrogate models; co-optimizes job-level and cluster-level objectives.
SigmaOS: Unifying Serverless and Microservice Tasks
SOSP2024
Single platform combining burst-parallel serverless functions with long-running microservices via a unified task abstraction.
B.4 RDMA & High-Speed Interconnects ▶
Exploiting RDMA, NVLink, InfiniBand, and CXL for distributed shared memory and collective communication. Key for ML training at scale.
Problem: All-reduce collectives are the bottleneck in >1000-GPU training; NVLink topology matters
Representative Papers
FastSwitch: Optimizing Parameter Server Architecture for Fast Model Parallel Training
SC2022
RDMA-based parameter server redesign; eliminates CPU involvement in gradient communication for GPU-GPU transfers.
Fast In-Network Lock Management Using Lock Fission
OSDI2024
RDMA-based in-network lock manager that decomposes locks via "lock fission" to reduce network round trips.
Cerebros: Evading the RPC Tax in Datacenters
ASPLOS2023
Bypasses OS for intra-datacenter RPCs via user-space RDMA; achieves 100ns p99 latency for distributed transactions.
B.5 Heterogeneous Computing (CPU+GPU+FPGA+CXL) ▶
Workload-aware orchestration across diverse compute and memory hierarchies. CXL enables memory pooling. FPGA for irregular workloads. Key trend: LLM inference on heterogeneous hardware.
Problem: Optimal workload placement across CXL memory, GPU HBM, and NVMe for LLM inference
Representative Papers
KTransformers: CPU/GPU Hybrid Inference for MoE Models
SOSP2025
Expert routing-aware offloading of MoE layers between CPU and GPU; achieves 5× throughput over GPU-only serving.
FlexGen: High-Throughput Generative Inference with a Single GPU
ICML2023
Offloads weights/KV-cache to CPU/NVMe using linear programming to find optimal tensor placement policy.
B.6 Collective Communication Optimization ▶
AllReduce, AllGather, ReduceScatter topology-aware algorithms. NCCL optimization, compression-aware collectives, ring/tree switching, and overlap with compute.
Problem: Communication-compute overlap in pipeline/tensor parallel training is nontrivial
Representative Papers
Overlap Communication with Dependent Computation in Large DNN Models
ASPLOS2023
Decomposes compute and communication into fine-grained primitives and schedules them in parallel via dependency analysis.
MSCCLang: A Domain-Specific Language for Collective Communication
ASPLOS2023
Expressive DSL for writing custom collective algorithms; synthesizes efficient implementations for arbitrary topologies.

◆NAS-Bench-360
◆NCCL-tests (allreduce benchmarks)
◆TPC-C/H for parallel DB

C
Distributed Systems
Consistency, fault tolerance, storage, and scheduling at scale
◼ Core / Evolving
Domain Signal: Classic problems (consensus, transactions, replication) are well-studied, but disaggregated architectures, serverless computing, and ML-integrated storage systems are reshaping the field. New venues: SOSP, OSDI, NSDI, EuroSys, FAST, ATC.
C.1 Disaggregated Memory & Storage ▶
Separates compute and memory/storage resources connected via CXL or RDMA. Enables independent scaling of memory pools. Critical for LLM serving (KV cache disaggregation) and cloud cost efficiency.
Problem: Memory utilization <50% in monolithic servers; LLM KV caches waste 30–40% of GPU memory
Representative Papers
Mooncake: A KVCache-Centric Disaggregated Architecture for LLM Serving
FAST2025
Separates prefill/decode clusters; multi-layer distributed KV cache pool with prefix-hashed object storage.
DistServe: Disaggregating Prefill and Decoding for Goodput-Optimized LLM Serving
OSDI2024
Separate GPU pools for prefill (compute-heavy) and decode (memory-heavy) phases; 2–3.8× latency improvement.
CXL and the Return of Scale-Up Architectures
HotOS2023
Argues CXL memory pooling enables a new class of scale-up architectures; challenges scale-out assumptions.
MIND: In-Network Memory Management for Disaggregated Data Centers
SOSP2021
In-network cache coherence and virtual memory for disaggregated RDMA memory; near-local memory performance.
C.2 Distributed Transactions & Consensus ▶
Serializability, snapshot isolation, and linearizability in geo-distributed or multi-datacenter settings. Active areas: RDMA-based OCC, deterministic databases, and flexible consistency models.
Problem: Cross-shard transaction throughput bounded by 2PC latency and coordination overhead
Representative Papers
Polyjuice: High-Performance Transactions via Learned Concurrency Control
OSDI2021
Learns a workload-specific concurrency control protocol using RL; outperforms hand-tuned OCC/2PL by 2–4×. Foundational gap paper — little follow-up work exists.
Towards Optimal Transaction Scheduling (MVSchedO)
VLDB2024
Schedule-first CC protocol; pre-orders transactions on hot keys to reduce makespan by up to 11×.
Sonata: Multi-Database Transactions Made Fast and Serializable
VLDB2025
Cross-database serializability via a novel timestamp protocol; eliminates per-shard coordinators.
RCBench: RDMA-Enabled Transaction Framework for Concurrency Control Analysis
VLDB Journal2023
Systematic benchmark for CC algorithms over RDMA; reveals RDMA changes the optimal CC protocol choice.
C.3 Serverless & Function-as-a-Service Systems ▶
Stateless function execution on elastic cloud infrastructure. Problems: cold start latency, state management, function chaining, and resource scheduling. Increasingly used for ML inference.
Problem: Cold starts take 100ms–10s; stateful workflows require external storage round trips
Representative Papers
ServerlessLLM: Low-Latency Serverless Inference for Large Language Models
OSDI2024
Checkpoint-based fast loading of LLM weights for serverless functions; reduces cold start from minutes to seconds.
Catalyzer: Sub-millisecond Startup for Serverless Computing with Initialization-less Booting
ASPLOS2023
Snapshots initialized sandbox state at microcontainer level; achieves <1ms cold starts for most functions.
Serialization-Free State Transfer in Serverless Workflows with RDMA Remote Memory Map
EuroSys2024
Passes state between chained functions via RDMA memory mapping, eliminating serialization overhead entirely.
C.4 Fault Tolerance & Resilient Distributed Training ▶
Checkpoint, recovery, and fault-aware scheduling for large-scale distributed DNN training. GPU failures become frequent at 10K+ GPU scale; recovery time dominates total training time.
Problem: A100/H100 GPU failure rates make fault-free 10K-GPU-day training impossible without recovery
Representative Papers
Gemini: Fast Failure Recovery in Distributed Training with In-Memory Checkpoints
SOSP2023
Asynchronous CPU-memory checkpointing; overlaps checkpoint with training; recovers from failure in seconds vs. minutes.
Oobleck: Resilient Distributed Training using Pipeline Templates
SOSP2023
Pre-computes multiple pipeline templates; hot-swaps to alternative pipeline configuration on failure without restarting.
Bamboo: Making Preemptible Instances Resilient for Affordable DNN Training
NSDI2023
Redundant computation in pipeline parallel training masks spot instance preemption; 3× cost reduction on AWS spot.
C.5 Cloud-Native Storage Systems (NVM, Tiered Storage) ▶
Persistent memory (NVM/Optane), CXL-attached storage, tiered memory hierarchies, and log-structured storage for cloud workloads. Intersection with ML data pipelines.
Problem: I/O bottleneck during LLM training data loading; tiered storage policy for KV caches
Representative Papers
TreeSLS: A Tree-structured Microkernel with Efficient Whole-system Persistence on NVM
SOSP2023
Best Paper Award. Whole-system checkpointing to NVM using a tree-structured OS kernel; μs-level recovery.
CacheGen: KV Cache Compression and Streaming for Fast LLM Serving
SIGCOMM2024
Encodes KV caches as a video-like bitstream; streams compressed caches across network for prefill reuse.
C.6 Cluster Scheduling & Resource Management ▶
GPU cluster schedulers for deep learning jobs: gang-scheduling, elastic training, multi-resource bin packing, and SLO-aware scheduling. Major system infrastructure for cloud ML platforms.
Problem: Fragmentation in GPU clusters leads to 30–50% idle GPU time across industry deployments
Representative Papers
Llumnix: Dynamic Scheduling for Large Language Model Serving
OSDI2024
Live request migration between LLM instances for load balancing; reduces P99 latency by 40% vs. static assignment.
Synergy: Looking Beyond GPUs for DNN Scheduling on Multi-Tenant Clusters
OSDI2022
CPU, memory, network are co-bottlenecks with GPU; joint multi-resource scheduling improves cluster throughput 2×.
Parcae: Proactive, Liveput-Optimized DNN Training on Preemptible Instances
NSDI2024
Predicts spot preemptions; proactively repartitions training to minimize wasted compute, 10× cost reduction.

D
Blockchain / Web3 Systems
Consensus, scalability, smart contracts, and decentralized ML
▲ Emerging / Selective
Domain Signal: Blockchain systems research in top venues (OSDI, NSDI, SOSP) focuses on high-throughput BFT consensus, ZK-proof systems, and on-chain/off-chain hybrid execution. The intersection with ML (decentralized training, verifiable inference) is nascent and high-opportunity. Most application-layer blockchain work appears in IEEE S&P, CCS, and domain-specific venues.
D.1 High-Throughput BFT Consensus ▶
Byzantine fault-tolerant protocols that scale to thousands of TPS. DAG-based BFT (Bullshark, DAG-Rider), HotStuff variants, and pipelining techniques.
Problem: Classical BFT protocols cap at ~1000 TPS; practical blockchains need 100K+ TPS
Representative Papers
Bullshark: DAG BFT Protocols Made Practical
CCS2022
DAG-structured mempool allows parallel proposal; consensus on committed anchors achieves 125K TPS on 50 nodes.
Shoal: A DAG BFT Protocol with Low Latency and High Responsiveness
arXiv2023
Pipelining and reputation-based leader rotation on top of Bullshark; sub-second latency at scale.
Mysticeti: Low-Latency DAG Consensus with Fast Commit Path
USENIX ATC2024
Concurrent block proposal in DAG; leader-only fast path reduces median latency to 0.5s for Sui blockchain.
D.2 ZK-Proof Systems & Rollups ▶
Zero-knowledge proofs (SNARKs, STARKs, PLONKs) for blockchain scalability (rollups) and verifiable computation. Prover performance is the critical bottleneck—GPUs/FPGAs are used.
Problem: ZK proof generation takes seconds to minutes; L2 rollup throughput limited by proof batch time
Representative Papers
Icicle: Hardware Acceleration for ZKPs using CUDA
arXiv2023
GPU-accelerated MSM (multi-scalar multiplication) and NTT (number-theoretic transform) primitives; 10–100× speedup over CPU provers.
cuZK: Accelerating Zero-Knowledge Proof with A Faster Parallel Multi-Scalar Multiplication Algorithm on GPUs
IEEE TPDS2023
Novel GPU MSM algorithm with better bucket partitioning; 3.5× over prior GPU MSM for Groth16 proofs.
Pianist: Scalable zkRollups via Fully Distributed Zero-Knowledge Proofs
IEEE S&P2024
Distributes ZK proof generation across multiple machines; linear scaling for Plonk-based rollup provers.
D.3 Blockchain-Based Decentralized ML ▶
Using blockchain for trustless FL aggregation, model marketplace, verifiable inference, and tokenized data contribution. Intersection of FL + blockchain + ZKP.
Problem: Verifying correct model aggregation or inference on-chain is computationally infeasible
Representative Papers
zkML: Verifiable Machine Learning Inference via Zero-Knowledge Proofs
arXiv2022
Compiles DNN inference into ZK circuits; enables on-chain verification that off-chain inference was correct.
EZKL: Scaling Up ML Inference Proofs with Ethereum
arXiv2023
Production ZK prover for ONNX models; enables on-chain verification of small neural network predictions.
FedChain: An Efficient and Secure Consensus Protocol based on Proof of Useful Federated Learning
IEEE TIFS2022
Replaces PoW mining with FL training as proof-of-work; verifiable gradient quality via hash commitments.
D.4 Smart Contract Systems & Parallel Execution ▶
Parallelizing smart contract execution across shards or within a block. Key challenge: detecting and handling transaction dependencies (read-write conflicts) at runtime.
Problem: Sequential EVM execution limits Ethereum to ~15 TPS; parallel execution requires conflict detection
Representative Papers
Parallel EVM: Concurrency Control for High-Throughput Smart Contracts
arXiv2023
Optimistic parallel execution with rollback on conflict detection; 5–20× throughput improvement over serial EVM.
Block-STM: Scaling Blockchain Execution by Turning Ordering Curse to a Performance Blessing
arXiv / PPoPP2023
Software transactional memory for in-block parallelism; used in production by Aptos blockchain at 160K TPS.
Open Research Gaps
◆Efficient ZK proofs for LLM inference (100M+ param)
◆Blockchain-native FL aggregation with verifiability
◆Parallel EVM with ML-predicted conflict graphs
◆Decentralized AI model governance on-chain
Open-Source Tools

◆Icicle (GPU ZK acceleration)

E
Edge Computing / Fog Computing
Inference, training, and orchestration at the network edge
⚡ High Potential
E.1 DNN Inference Optimization at Edge ▶
Model compression, quantization, pruning, and split inference for resource-constrained edge devices (phones, Raspberry Pi, Jetson). Latency and energy are primary constraints.
Problem: LLM inference on mobile: 7B model = 14GB; typical phone has 6–8GB RAM
Representative Papers
LLM in a Flash: Efficient Large Language Model Inference with Limited Memory
arXiv (Apple)2024
Offloads LLM weights to flash storage; intelligent prefetching achieves 25 tok/s on iPhone using sparsity-aware loading.
EdgeBERT: Sentence-Level Energy Optimizations for Latency-Aware Multi-Task NLP Inference
MICRO2022
Early-exit BERT for edge: adapts compute to input complexity; 7× energy reduction vs. standard inference.
Characterizing Mobile SoC for Accelerating Heterogeneous LLM Inference
SOSP2025
Characterizes Apple M-series and Qualcomm SoC for LLM inference; finds CPU+GPU+NPU co-execution optimal.
E.2 Split Computing & Model Partitioning ▶
Partitions DNN layers across edge device and cloud server. Intermediate feature compression and adaptive splitting based on bandwidth. Addresses the memory-bandwidth tradeoff.
Problem: Intermediate feature tensors can be larger than model weights; split point selection is dynamic
Representative Papers
SPINN: Synergistic Progressive Inference of Neural Networks over Device and Cloud
MobiCom2022
Progressive early-exit + split computing; dynamically adapts to network bandwidth and device battery state.
Elf: Accelerate High-resolution Mobile Deep Vision with Content-aware Parallel Offloading
MobiCom2022
Content-aware spatial partitioning of image frames across device/edge for video analytics pipelines.
E.3 Hierarchical Federated Learning (Device-Edge-Cloud) ▶
Three-tier FL: device trains locally, edge aggregates within cluster, cloud aggregates globally. Reduces communication to cloud; enables local personalization. Active area with many systems papers.
Problem: Optimal aggregation frequency at each tier; edge server bandwidth is shared among thousands of devices
Representative Papers
FedHiSyn: A Hierarchical Synchronous Federated Learning Framework with Grouped Clients
ICS2022
Groups clients by speed; synchronizes within groups before cross-group aggregation; reduces straggler effect.
HFL-TS: Hierarchical Federated Learning with Topology-Aware Scheduling
IEEE TPDS2023
Topology-aware client grouping at edge; considers link bandwidth for scheduling aggregation rounds.
E.4 Edge Orchestration & Resource Management ▶
Kubernetes-based edge orchestration, multi-access edge computing (MEC), offloading decisions, and SLA-aware scheduling for heterogeneous edge nodes.

Potential Areas Worth Investigating vs. Areas Likely Saturated

Potentially Crowded (may be difficult to contribute): Basic KV-cache management for LLM serving (dozens of papers), simple FedAvg variants for non-IID data, GPU kernel optimization without architectural novelty, another Bitcoin-style blockchain paper, standard BERT fine-tuning at edge.
